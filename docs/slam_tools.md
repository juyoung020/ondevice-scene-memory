- 재위치: ORB-SLAM3 는 회전 · 크기 불변 ORB 낱말로 전체 키프레임에서 찾아 PnP 검증. RTAB-Map 원본은 우리 포팅판과 같은 구조라 BRIEF 변별 약점이 남음. cuVSLAM 은 장소 인식 기반 `localize_in_map` 을 우리가 불러 줘야 함.
- 합치기: ORB-SLAM3 Atlas 는 놓치면 새 지도를 열고 모든 지도를 상대로 장소 인식을 계속, 맞으면 합쳐 다시 최적화.
- 중력: 스테레오 전용은 추정기에 중력이 없음 → 시작 때 IMU 중력으로 지도 전체를 한 번 돌림(우리가 붙임).
- 물체 중복: 루프 · 합치기 뒤 바뀐 키프레임 자세를 물체 지도에 다시 반영하는 연결은 어느 도구든 우리가 만듦.
- 번짐 · 롤링 셔터는 입력을 적외선(글로벌 셔터)으로 바꿔서 풀림. 빈틈은 녹화기(램 디스크 · SSD)로 고침.
- 먼 깊이: ORB-SLAM3 는 기준선 약 40 배(D435 약 2 m)보다 먼 점을 삼각측량으로 다룸. 물체 지도 깊이 오차는 D455 로만 줄어듦.

## 추천

1. **ORB-SLAM3 적외선 스테레오 + Atlas**(IMU 는 중력 맞추기에만). 재위치 · 합치기 · 루프 보정 내장 → `pose_issues.md` "다시 붙게 하는 순서" 1–8 을 만들 필요 없음. 시각차 · IMU 재보정 없음, 보정은 카메라 공장값. 무료(GPLv3) · CPU. 우리가 만들 것: 시작 중력 맞추기, 바뀐 키프레임 자세를 물체 지도에 반영. 소스 WSL `~/slam-bench/src/ORB_SLAM3`.
2. **cuVSLAM 적외선 스테레오**. 설치 가장 쉬움, 다음 날 재위치(초기 추정 없음) 강점, NVIDIA GPU 필수(가벼움), 합치기 · 빈틈 뒤 동작 미확인.
3. **RTAB-Map 원본**. 중력 · 시각차는 잘 메우나 재위치 변별 약점 그대로, "RTAB-Map 통째 교체" 방침과 부딪힘.

Basalt · OpenVINS 는 추적 전용(재위치 · 합치기 · 루프 없음). 학습 기반(DROID · MASt3R-SLAM · VGGT-SLAM · Gaussian Splatting)은 큰 GPU · 지도 저장/다음 날 재위치 없음으로 제외. Spectacular AI 는 D435(i 없음) 미지원.

## 시험

- 녹화: 적외선 좌우(프로젝터 끔, 640×480, 30 fps, 노출 상한 4–8 ms) + IMU EuRoC 꼴 + 컬러 · 깊이, 빈틈 0.
  - A: 2–3 초 정지 → 방 한 바퀴 → 처음 자세로 끝, 중간에 렌즈를 3–5 초 가렸다가 다른 방향에서 뗌
  - B: 다음 날 같은 방, 다른 시작 위치
  - 지금 있는 적외선 녹화: GitHub 릴리즈 `recordings-v2` 에 `ir_loop_off` 뒷조각(part-01)만 올라가 있음. `ir_loop_on` · `ir_off1/2` · `ir_on1` 과 part-00 은 다시 올려야 함
- ORB-SLAM3 스테레오를 WSL 별도 폴더에 빌드해 A 를 돌리고 Atlas 저장 → B 를 그 Atlas 로 시작.
- 판정: 끝–시작 위치 · 각도 차, 천장 면 기울기(목표 3° 미만), 가린 뒤 같은 지도로 돌아왔는지 · 새 지도가 합쳐졌는지, B 가 A 지도에 붙었는지.

## 시험 결과

2026-11-25, 데스크톱 WSL(Ryzen 9 9950X, CPU 만), ORB-SLAM3 4452a3c. 도구 · 설정 · 실행 기록은 WSL `~/slam-bench/tools/orb3`(실행기 `orb3_run`, 판정 `traj_eval` · `pnp_pair`, 설정 `d435_ir_rgbd.yaml` · `d435_ir_stereo.yaml`) · `~/slam-bench/runs`.

**시험 조건(계획과 다른 점)**
- 릴리즈에서 건진 것: 적외선 왼쪽 1,800 장 전부, 원시 깊이 1,800 장 전부, IMU, `calib.json`. 적외선 오른쪽은 564 장(31 %, 흩어져 있음), `rgb/` · `depth/` 는 없음.
- 그래서 ORB-SLAM3 를 **적외선 왼쪽 + 원시 깊이(RGB-D 모드)** 로 돌림. 깊이가 같은 적외선 좌우에서 나온 것이라 입력 정보는 스테레오와 같지만 스테레오 모드 자체의 결과는 아님. 오른쪽 564 장만으로 돌린 스테레오는 초당 9 장꼴이라 리셋 7 번 · 위치 있음 35 % 로 판정에 못 씀.
- 우리 판에는 같은 입력(적외선 왼쪽을 컬러 자리에, 원시 깊이, 적외선 기준 IMU 변환)을 줌.
- `ir_loop_off` 녹화 자체에 빈틈: 79.6 초 동안 589 장(24.7 %) 빠짐, 큰 빈틈 5 개(1.43 · 1.33 · 5.94 · 5.64 · 5.20 초). IMU 는 카메라보다 17.3 초 먼저 끝나 기울기는 +62 초까지만 잼.
- 끝–시작 기준값: 장면 0 과 끝 무렵 장면(1660 · 1670 · 1700)을 ORB 짝 + 깊이 + PnP 로 직접 잼(실제 차 0.08–0.10 m · 1.3–2.8°). 표의 오차는 궤적이 낸 상대 자세와 이 값의 차. 마지막 장면(1799)은 실제로 0.5 m · 23° 떨어져 있어 기준으로 안 씀.
- 레이저 켠 녹화 · 다른 녹화로 Atlas 시작은 녹화가 없어 못 함. Atlas 는 같은 녹화의 뒷부분을 새 실행으로 시작하는 것으로 대신함.

**결론 · 다음 단계**
- 같은 입력에서 재위치 · 합치기 · 기울기 · 한 바퀴 오차가 모두 우리 판보다 크게 나음 → 위치 추적을 ORB-SLAM3 로 바꿀 만함.
- 붙이기: `slam/orb3` 브랜치의 C 래퍼(`slam/cpp/orb3.cc`) · 백엔드를 `opt/integrate` 로 가져옴 → 입력은 적외선 왼쪽 + 원시 깊이(또는 좌우) → IMU 는 시작 정지 구간 평균 가속도로 지도를 한 번 돌리는 데만 → `MapChanged`(합치기 · 최적화) 때 키프레임 자세를 물체 지도에 다시 반영 → 패치에 저장 결함 수정 2 개 추가 → Atlas 저장 · 불러오기를 기본 동작으로.
- 먼저 할 것: 릴리즈에 녹화 다시 올리기(`ir_loop_off` part-00, `ir_loop_on` · `ir_off2`, `SHA256SUMS`) → 스테레오 모드 · 레이저 켬 · 다른 녹화 Atlas 시작 재시험, Pi 5 에서 속도.
