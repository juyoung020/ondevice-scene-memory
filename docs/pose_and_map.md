# 일반 카메라로 포즈와 3D 지도 얻기

USB RGB 카메라에는 깊이도 IMU 도 없다. 그래서 두 가지를 영상만으로 풀어야 한다.

- **포즈**: 카메라가 지금 어디서 어느 쪽을 보는지 (6자유도)
- **깊이**: 화면의 각 점이 얼마나 먼지 → 3D 점

단안 카메라만의 고유 문제:

| 문제 | 왜 생기나 |
|---|---|
| 크기 모호성 | 작은 방을 가까이서 본 것과 큰 방을 멀리서 본 것이 똑같이 찍힘 → 미터 단위가 안 나옴 |
| 크기 떠밀림 | 오래 움직이면 그 비율이 조금씩 변함 |
| 초기화 | 제자리 회전만 하면 깊이 단서가 없어 시작을 못 함 |
| 흐림·무늬 없는 벽 | 특징점이 안 잡혀 추적이 끊김 |

## 포즈 후보

| # | 방법 | 크기(m) | 손떨림·흰 벽 | 보드에서 | NPU 쓰임 |
|---|---|---|---|---|---|
| 1 | **고전 단안 SLAM** (ORB-SLAM3 단안, stella_vslam) | 없음 → 깊이 모델이나 마커로 맞춰야 함 | 약함 | CPU 로 가능 | 없음 |
| 2 | **가짜 RGB-D**: NPU 깊이 모델 출력을 깊이 카메라처럼 RGB-D SLAM 에 넣음 (ORB-SLAM3 RGB-D 모드) | 깊이 모델이 줌 | 초기화 즉시, 제자리 회전 OK | 깊이 모델이 추적 속도만큼 빨라야 함 | 깊이 |
| 3 | **학습 특징점 + 고전 최적화**: 특징점 추출(XFeat / SuperPoint)을 NPU 에서, 매칭·BA 는 CPU | 2 와 같이 깊이로 | ORB 보다 강함 | 가능성 높음 | 특징점 + 깊이 |
| 4 | **학습형 SLAM 통째로** (DROID-SLAM, DPVO, MASt3R-SLAM, VGGT 류) | 일부 줌 | 가장 강함 | 큰 GPU 전제, DX-M1 엔 무거움 | — (PC 기준선으로만) |
| 5 | **IMU 하나 추가** (값싼 6축 센서) → VIO (VINS-Mono, OpenVINS) | IMU 가 줌 | 강함 | CPU 로 가능 | 없음 |

추천 출발점: **2번**(NPU 깊이 → RGB-D SLAM). 크기·초기화 문제가 한 번에 풀리고 NPU 를 핵심에 쓴다.
더 갈 곳: **3번**(SLAM 앞단을 NPU 로 포팅 — 온디바이스 과목에 가장 잘 맞는 기여). 4번은 PC 에서 정답에 가까운 기준선으로 비교용.
5번은 하드웨어가 하나 늘지만 가장 확실하다 — 2·3 이 손떨림에 무너지면 꺼낸다.

## 크기(m) 를 YOLO 로 잡기 — 물체 크기 앵커

YOLO-seg 를 **우리가 고른 물체로 직접 학습**하므로, 각 물체의 실제 크기를 줄자로 재 두면 정확한 크기 사전값이 생긴다.
그 물체가 보일 때마다 크기 기준이 하나 생기는 셈이다.

| 쓰는 법 | 식 | 비고 |
|---|---|---|
| 거리 바로 구하기 | 거리 Z = 초점거리 f × 실제 높이 H / 화면 높이 h(px) | 깊이 모델 없이 물체 3D 위치가 나옴. 한 장으로 됨 |
| SLAM 크기 맞추기 | 크기 비율 = 실제 크기 / SLAM 좌표로 복원한 그 물체 점구름 크기 | 여러 물체·여러 프레임 중앙값 → 1번 단안 SLAM 의 크기 모호성·떠밀림을 계속 보정 |
| 깊이 모델 크기 맞추기 | 마스크 안 깊이 중앙값 ↔ 위 거리 Z | 2번의 프레임별 크기 맞춤 기준으로 SLAM 점 대신·같이 사용 |

조심할 것:
- 화면 가장자리에 **잘린 물체**, **가려진 물체**는 크기를 틀리게 준다 → 마스크가 화면 끝에 닿거나 깊이상 가려지면 앵커에서 뺀다.
- 박스 높이는 **보는 각도**에 따라 변한다 (눕힌 컵) → 높이·너비 중 방향에 덜 민감한 값(세워 두는 물체의 높이), 또는 3D 점구름 크기 비교를 우선.
- 같은 클래스라도 크기가 다른 물체가 여럿이면 → 우리 데이터에선 물체 하나 = 클래스 하나로 두거나, 크기 편차가 작은 것(A4 종이, 모니터, 문 등)만 앵커로.
- 앵커 한 번은 잡음이 크다 → 시간에 따라 이상치 빼고 중앙값.

효과: **1번(단안 SLAM) + 물체 크기 앵커**만으로도 미터 단위 지도와 물체 위치가 나온다 → 깊이 모델 없이도 끝까지 가는 가장 가벼운 길. 깊이 모델은 물체의 모양(점구름)과 빈 공간 지도를 더 촘촘히 하는 데 쓴다.
초기화(제자리 회전)·흰 벽 끊김은 크기 앵커로 안 풀린다 — 그건 여전히 2·3·5번 몫.

## 3D 지도 갱신

### 1. 지도를 키프레임에 묶어 둔다

물체 점·깊이 점을 **전역 좌표로 바로 굳히지 않고**, 그걸 본 키프레임 기준 좌표로 저장한다.
전역 위치 = 키프레임 포즈 × 키프레임 안 좌표.
루프 클로징·BA 로 포즈가 고쳐지면 지도도 다시 계산할 필요 없이 따라 고쳐진다.

### 2. 깊이 크기를 프레임마다 맞춘다

깊이 모델은 프레임마다 크기가 조금씩 흔들린다. 매 키프레임 SLAM 이 가진 희소 3D 점과 깊이 모델 값을 비교해 `크기·오프셋`을 최소제곱(이상치 제거)으로 맞춘 뒤 쓴다. 이렇게 하면 같은 물체가 프레임마다 번지지 않는다.

### 3. 지도 표현

| 층 | 무엇 | 왜 |
|---|---|---|
| 희소 점 | SLAM 이 쓰는 특징점 | 포즈 추적용 |
| 거친 점유 격자 (복셀) | 공간 모양 | 뷰어 배경, "이 근처가 비었나" |
| 물체 점구름 | 물체마다 마스크에서 뽑은 3D 점 | 위치·크기·관계 계산 |

### 4. 물체 바뀜 처리

| 상황 | 판단 |
|---|---|
| 기억 속 물체 자리가 지금 화면에 보이는데(깊이로 가려짐 아님 확인) 검출이 안 됨 | 있을 확률 ↓ → 일정 이하면 "사라짐" |
| 다른 곳에서 벡터가 아주 비슷한 같은 클래스가 보임 | "옮겨짐" → 위치 갱신 |
| 처음 보는 것 | 새 노드 |

## 비교 방법 (보드 전에 PC 에서)

1. **정답 포즈 있는 공개 데이터**: TUM RGB-D (깊이는 버리고 RGB 만 사용, 정답 깊이는 깊이 모델 평가에 사용), ScanNet 일부. 후보마다 ATE(cm)·크기 오차·끊긴 횟수.
2. **우리 카메라로 찍은 손 영상**: 실제 USB 카메라·손떨림·흐림 조건. 책상에 ArUco 마커 몇 장 → 마커로 정답 포즈 근사.
3. 이긴 방법을 보드로 옮겨 같은 영상으로 다시 재기 (PC vs 보드 차이 = 양자화·속도 영향).

## 먼저 확인할 것

- 깊이 모델 후보들이 DX 컴파일러에서 `.dxnn` 이 되는지, 되면 NPU 에서 몇 ms 인지 (2번 성립 조건)
- XFeat / SuperPoint 가 `.dxnn` 이 되는지 (3번 성립 조건)
- ORB-SLAM3 가 Pi5 에서 빌드·실시간 되는지
