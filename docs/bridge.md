# 연결 프로그램: RTAB-Map → memmap 장면 스트림

`bridge/`(C++, CMake)의 `rtab_bridge` 가 RGB-D 입력을 RTAB-Map 에 넣어 장면마다 위치를 구하고, 위치 + 컬러 + 컬러에 맞춘 깊이를 memmap 으로 흘려보낸다. memmap 은 `--stream` 으로 받아 지금의 TUM·카메라 입력과 같은 지도·물체·씬그래프 단계를 돈다.

```
RealSense D435 (컬러 RGB8 + 깊이 Z16, 640×480@30)      TUM 폴더 재생(rgb.txt·depth.txt, 시험용)
        │ 깊이 → 컬러 정렬(depth_align.cpp, rs2::align)          │
        └──────────────┬───────────────────────────────────┘
                       ▼
     RTAB-Map 위치 추적(매 장, Odometry) + 지도 갱신(Rtabmap::process, DetectionRate 1/초)
                       │ 장면 위치 = 지도 보정 × 위치 추적 × 광학 축
                       ▼  쓰기 스레드(큐, 밀리면 버림 또는 기다림)
           표준출력·파일·이름 있는 파이프 ──→ memmap --stream -  (분할 → 표면·물체·씬그래프)
```

처리 순서(위치 추적 → 놓침이면 새 지도 → DetectionRate 로 지도 노드 고르기 → `Rtabmap::process`)는 RTAB-Map 의 `rtabmap-rgbd_dataset` 도구와 같다. 오프라인 위치 파일(`--gt`)도 이 도구로 만들었다.

## 쓰는 법

```bash
# 빌드(WSL·보드): RTAB-Map·librealsense 설치 경로를 알려 줌. librealsense 가 없으면 TUM 재생만 들어감
cmake -S bridge -B ~/build/bridge -G Ninja -DCMAKE_PREFIX_PATH="$HOME/opt/rtabmap;$HOME/opt/librealsense"
ninja -C ~/build/bridge

# 카메라 → memmap(실시간)
rtab_bridge --realsense --config docs/rtabmap_pi.ini --send-every 2 \
  | memmap --stream - --every 1 --live 1 --surface --seg <분할 모델> --max-depth 3.5 --out data/memory/live

# TUM 재생(카메라 없이): --rate 1 이면 찍은 시각대로(밀리면 건너뜀), 생략하면 최대 속도로 빠짐없이
rtab_bridge --tum data/d435/rgbd_dataset_freiburg3_office_sync --config docs/rtabmap_pi.ini \
  | memmap --stream - --every 2 --surface --seg models/yolo26s-seg.onnx --max-depth 3.5 --out data/memory/office_stream
```

| `rtab_bridge` 인자 | 뜻 |
|---|---|
| `--realsense [--align rs2] [--serial S] [--size 640x480] [--fps 30]` | RealSense 입력(IMU 는 켜지 않음) |
| `--tum <폴더> [--rate R]` | TUM 폴더 재생. 보정값은 memmap `tum.rs` 와 같이 폴더 이름으로(freiburg1·2·3) |
| `--config <ini>` | RTAB-Map 설정(`[Core]`), 그 뒤 `--Group/Name 값` 으로 덮어씀 |
| `--out -\|<파일>` | 스트림 출력(기본 표준출력). 파일로 남겨 두면 `memmap --stream <파일>` 로 다시 돌릴 수 있음 |
| `--send-every N` | N 장마다 보냄(위치 추적은 모든 장면) |
| `--queue N`, `--block`·`--drop` | 쓰기 큐 길이(기본 4), 큐가 차면 기다림·가장 오래된 장면 버림. 기본은 최대 속도 재생 = 기다림, 카메라·`--rate` = 버림 |
| `--poses <파일>` | 보낸 위치(TUM 형식, OpenCV 카메라 → RTAB-Map 지도) |
| `--final-poses <파일>` | 끝에 최적화된 지도 노드 위치(TUM 형식, 같은 좌표) |
| `--stats <파일>` | 장면별 시간·놓침·새 지도·지도 보정·특징 수(CSV) |
| `--db <파일>` | RTAB-Map 데이터베이스로 남김(`rtabmap-databaseViewer` 로 볼 수 있음) |

RTAB-Map 로그는 표준오류로 나간다(표준출력은 시작할 때 떼어 스트림 전용으로 쓴다).

| `memmap` 인자 | 뜻 |
|---|---|
| `--stream -\|<파일>` | 장면 스트림 입력. 위치·깊이는 받은 그대로, 분할은 memmap 이 돌림. `--every N` 은 받은 장면 N 장마다 |
| `--no-level` | 받은 위치의 z 를 그대로 위로 씀(기본은 아래 "바닥 맞추기") |
| `--rebuild-every S`, `--kf-store-mb M`, `--no-rebuild` | 루프 클로저 뒤 다시 쌓기 간격(초, 기본 5, 0 = 끝에만)·장면 보관 예산(MB, 기본 3000)·끄기(아래 "루프 클로저 뒤 다시 쌓기") |

memmap 출력은 TUM 입력과 같고, 스트림이면 `poses_est.txt`(받아 쓴 위치, 수평 맞춘 세계)가 더 생긴다. 모든 입력에서 `poses_map.txt`(지도에 넣은 장면의 카메라 위치, 메쉬 좌표)가 생긴다.

## 스트림 형식

장면 하나 = 머리 176 바이트 + RGB8(`w×h×3`, 행 우선, R·G·B) + 깊이(`w×h` 개 u16). 장면 사이에 그래프 블록(아래)이 끼어 온다. 모든 수는 리틀 엔디언, 실수는 IEEE 754. 보내는 쪽이 닫으면 끝.

| 위치 | 형 | 칸 | 값 |
|---|---|---|---|
| 0 | char[4] | 표시 | `MMF1` |
| 4 | u32 | 머리 크기 | 176 |
| 8 | u32 | 상태 | 1 = 위치 놓침(위치 칸 무시), 2 = 이 장면에서 새 지도 시작, 4 = 이 장면에서 지도 보정(루프 클로저·최적화)이 바뀜 |
| 12 | u32 | 지도 번호 | RTAB-Map 지도 번호(새 지도마다 늘어남) |
| 16 | u64 | 장면 번호 | 입력 순서(보내지 않은 장면도 셈) |
| 24 | f64 | 시각 | 초(TUM: 파일 시각, RealSense: 컬러 장면 시각) |
| 32 | f64[12] | 위치 | 3×4 행 우선 `[R | t]`: OpenCV 카메라 → 세계 |
| 128 | f64[4] | 보정값 | fx, fy, cx, cy(컬러, 왜곡 없음) |
| 160 | u32 ×2 | 크기 | w, h |
| 168 | f32 | 깊이 배율 | 깊이 값 / 미터(RealSense 1000 = mm, TUM 5000). 0 = 깊이 없음 |
| 172 | u32 | 기준 노드 | 이 장면의 기준 RTAB-Map 지도 노드 id(`getLastLocationId()`, 0 = 없음). 장면 위치 = 그 노드 위치 × 상대 위치 |

그래프 블록 = 머리 16 바이트 + 노드마다 104 바이트. 지도 갱신(`Rtabmap::process`) 뒤 새로 생기거나 움직인(3×4 행렬 원소가 1e-3 넘게 바뀐) 노드만 담아 그 장면보다 먼저 보낸다. 쓰기 큐가 차도 버리지 않는다.

| 위치 | 형 | 칸 | 값 |
|---|---|---|---|
| 0 | char[4] | 표시 | `MMG1` |
| 4 | u32 | 머리 크기 | 16 |
| 8 | u32 | 노드 수 | n |
| 12 | u32 | 예약 | 0 |
| 16 + 104·i | u32, u32 | 노드 id, 예약 | `getLocalOptimizedPoses()` 의 id, 0 |
| 24 + 104·i | f64[12] | 노드 위치 | 3×4 행 우선, OpenCV 카메라 → 세계(장면 위치와 같은 좌표: 노드 위치 × opticalRotation) |

깊이는 컬러 화소 격자에 맞춘 것. memmap 은 `값 / 깊이 배율` 로 미터를 만든다(TUM 입력 `tum.rs` 와 같은 계산이라 같은 영상이면 같은 수).

## 좌표 약속

| | 카메라 축 | 세계 축 |
|---|---|---|
| memmap(`r`, `p`) | OpenCV: x 오른쪽, y 아래, z 앞 | x·y 수평, **z 위**(바닥·점유 지도·방 나누기가 z 를 위로 씀) |
| RTAB-Map 위치 추적 | 몸체: x 앞, y 왼쪽, z 위(ROS) | 지도: 첫 장면의 몸체 축(IMU 없으면 z 는 처음 든 카메라의 위) |
| 몸체 → 광학 축 | `CameraModel::opticalRotation()` = `[[0,0,1],[-1,0,0],[0,-1,0]]`(열 = 광학 x·y·z 를 몸체로) | |

- 연결 프로그램이 보내는 위치 = `지도 보정 × 위치 추적 × opticalRotation`. 첫 장면은 정확히 `opticalRotation` 이 되고, 이것은 memmap 웹캠 입력의 첫 자세(`r0 = [[0,0,1],[-1,0,0],[0,-1,0]]`, 수평으로 앞을 봄)와 같다. 그래서 회전을 따로 바꾸지 않는다.
- **바닥 맞추기**: RTAB-Map 지도의 z 는 첫 장면 카메라가 기운 만큼 기울어 있다. memmap 은 웹캠 입력과 같은 방법(장면마다 RANSAC 으로 찾은 수평면 법선 15 개 이상이 10° 안에서 합의)으로 위쪽을 정해 그 뒤 오는 모든 위치에 같은 회전을 곱한다. 합의 전 장면은 지도에 넣지 않는다.
- 높이: memmap 이 첫 장면의 바닥 높이(카메라 아래 깊이 점 95 %)로 원점을 바닥에 맞춘다(TUM 입력과 같음).
- 코드로 확인한 것(검증 표의 `자세 차이`): 보낸 위치를 정답에 맞춘 뒤 카메라 자세 차이가 사무실 1–2°, 책상 3–6°. 몸체 축을 그대로 보냈다면 opticalRotation 의 회전각인 120° 가 나온다. memmap 이 받아 쓴 위치(`poses_est.txt`)를 보낸 위치에 맞추면 위치 차이 0, 자세 차이 0°(바닥 맞추기 회전 한 번만 다름).

## 놓침·새 지도·루프 클로저

- 위치를 못 구한 장면은 상태 1 로 보내고 memmap 은 지도·물체에 넣지 않는다(개수는 결과 JSON `stream_lost`).
- `Odom/ResetCountdown 1` 이면 놓친 다음 장면에서 위치 추적이 마지막 위치로 다시 시작하고, 연결 프로그램은 `triggerNewMap()` 으로 새 지도를 연다(도구와 같음). 그 장면은 위치가 "마지막 위치"로 채워질 뿐이라 놓침 + 새 지도(1 + 2)로 보낸다. 이후 장면은 새 지도에서 이어지고, 옛 지도와 루프가 닫히면 RTAB-Map 이 두 지도를 한 좌표로 합친다.
- 루프 클로저로 지도 보정이 바뀌면 그 장면부터 위치가 보정된 좌표로 오고(상태 4), 그 앞에 움직인 노드를 담은 그래프 블록이 온다.

### 루프 클로저 뒤 다시 쌓기(memmap)

- memmap 은 지도에 넣은 장면(컬러, 깊이 mm, 분할 결과, 카메라 높이)을 기준 노드와 그 노드에서 본 상대 위치로 보관한다(`kfstore.rs`). 상대 위치는 받을 때 `기준 노드 위치⁻¹ × 장면 위치` 로 구한다. RTAB-Map 에서 마지막 노드 위치 = 지도 보정 × 그 노드의 오도메트리 위치라, 이 값은 오도메트리 상대 움직임과 같고 루프 클로저로 바뀌지 않는다.
- 그래프 블록에서 보관한 장면의 노드가 2 cm 또는 1° 넘게 움직이면 표시해 두고, `--rebuild-every` 초(기본 5)에 한 번까지 점유 지도·표면(TSDF)·점 지도·물체·지나온 길을 비우고 보관한 장면을 `지금 노드 위치 × 상대 위치` 로 처음부터 다시 쌓는다(실시간 장면과 같은 `map_frame`, 물체 병합 후처리는 15 장마다). 스트림이 끝났을 때 표시가 남아 있으면 한 번 더 쌓아 결과 지도·물체·`poses_map.txt` 가 끝난 그래프를 따른다.
- 다시 쌓으면 출력의 실행 번호가 바뀌어 뷰어가 받은 표면·점 조각을 비우고 새로 받는다. 물체 id 는 이어서 쓴다.
- 보관 예산 `--kf-store-mb`(기본 3000): 넘으면 보관한 장면을 하나 걸러 버리고 이후 두 배 간격으로 보관한다. 640×480 한 장은 약 1.5 MB. `--rebuild-every 0` 은 끝에만, `--no-rebuild` 는 보관도 다시 쌓기도 하지 않는다.
- 기준 노드를 모르는 장면(노드가 생기기 전, 다른 지도에서 끊긴 노드)은 받은 위치 그대로 쌓는다.

## 검증 (WSL Ubuntu 24.04, TUM 재생, 2026-11-05)

`bridge/tools/check_tum.sh` 로 시퀀스마다 세 번 돌려 견줌. RTAB-Map 0.24.2 를 Ubuntu 패키지(OpenCV 4.6 xfeatures2d 없음, g2o)로 빌드해 기본 특징이 GFTT/ORB, 최적화기가 g2o 다(보드와 같은 조합, [board_bridge.md](board_bridge.md)). memmap 은 ONNX Runtime CPU 로 YOLO26s-seg 분할, `--depth kinect --surface --every 2`, 최대 거리 사무실·책상 3.5 m, 복도 4 m.

- **기준**: 같은 설정 + 모든 장면을 지도 노드로 끝까지 돌려 최적화한 위치 → `memmap --tum --gt`(오프라인 경로).
- **같은 위치 오프라인**: 스트림 실행이 보낸 위치 파일 그대로 → `memmap --tum --gt`. 스트림과 위치가 같고 입력 경로만 다르다.
- **스트림**: `rtab_bridge | memmap --stream -`(보드와 같은 설정, 장면이 들어올 때의 위치).

위치 오차는 정답 기준 `ate`(맞춘 뒤 RMSE), 표면은 `surfcmp --align`(스트림 → 상대, 꼭짓점 5 cm 안 비율 / 거리 중앙값).

| 시퀀스 | 경로 | 위치 오차 | 물체 | 표면: 스트림 대 이 경로 |
|---|---|---|---|---|
| 사무실 2,488 장 | Windows RTAB-Map 기본(BRIEF + GTSAM) 위치 파일 | 2.0 cm | 49 | — |
| | 기준 | 3.8 cm | 48 | 0.77 / 2.7 cm |
| | 같은 위치 오프라인 | 6.4 cm | 54 | **0.98 / 0.8 cm** |
| | 스트림 | 6.4 cm(받은 위치) | **54** | — |
| 복도(D435i) 1,658 장 | 기준 | 0.25 m | 6 | 0.58 / 3.0 cm |
| | 같은 위치 오프라인 | 0.34 m | 6 | **0.99 / 1.1 cm** |
| | 스트림 | 0.34 m | **6** | — |
| fr1 책상 573 장 | 기준 | 4.2 cm | 23 | 0.73 / 3.0 cm |
| | 같은 위치 오프라인 | 10.0 cm | 23 | **0.98 / 1.2 cm** |
| | 스트림 | 9.1 cm(받은 장면만) | **22** | — |

- **연결은 그대로 전달**: memmap 이 받아 쓴 위치(`poses_est.txt`)를 보낸 위치(`--poses`)에 맞추면 세 시퀀스 모두 위치 차이 0.0000 m, 자세 차이 중앙 0.00°(최대 0.17°, 파일의 소수 6 자리). 같은 위치를 오프라인으로 넣은 결과와 물체 수가 같고(책상 22 대 23), 표면 98 % 가 5 cm 안·중앙 1 cm. 남는 차이는 세계를 세우는 방법(스트림: 바닥 합의, 오프라인: 경로 평면)이 달라 3 cm 표면 칸이 다르게 놓이는 것과, 바닥 합의 전 첫 15 장이 빠지는 것.
- **스트림 위치는 기준보다 덜 정확**: 기준은 끝난 뒤 모든 장면을 루프 클로저까지 반영해 다시 최적화한 위치이고, 스트림은 그 장면이 들어온 순간의 위치다. 사무실 3.8 → 6.4 cm, 책상 4.2 → 10 cm, 복도 0.25 → 0.34 m. 지도에는 아래 "루프 클로저 뒤 다시 쌓기 검증" 처럼 다시 쌓기가 끝난 그래프 위치를 반영한다(위 표의 스트림 줄은 다시 쌓기를 넣기 전 측정).
- 같은 설정도 실행마다 흔들린다(RTAB-Map 안 병렬 처리): 사무실 보낸 위치 4.0 · 4.9 · 6.4 cm, 책상 지도 노드 4.4–10.4 cm.
- 자세 차이(정답에 맞춘 뒤 중앙): 사무실 2.3°, 책상 4.4°. 복도는 정답 자세의 축 약속이 달라(Digiteo 정답) 자세 비교에서 뺐다.
- 세 시퀀스는 놓침 0. 놓침 경로는 fr1 책상에서 장면 150–249 를 빼 큰 틈을 만든 재생으로 확인: 틈 다음 장면(150)이 놓침 + 새 지도(상태 1 + 2)로 오고 memmap 은 그 한 장만 빼고(`stream_lost` 1) 계속 쌓았다. 61 장 뒤(211) 루프 클로저로 두 지도가 합쳐지며 상태 4 가 왔다.

### 루프 클로저 뒤 다시 쌓기 검증 (WSL, 2026-11-06)

사무실 2,585 장을 `rtab_bridge --config docs/rtabmap_pi.ini --out <파일>` 로 한 번 녹화(루프 클로저 12 번, 그래프 블록 84 개·노드 682 개)하고, 같은 스트림 파일로 memmap(`--depth kinect --surface --every 2 --max-depth 3.5`)을 돌려 견줌. 위치 오차는 지도에 넣은 카메라 위치(`poses_map.txt`)의 `ate`(정답 기준).

| memmap | 지도 위치 오차 | 물체 | 키프레임/초 | 최대 메모리 |
|---|---|---|---|---|
| `--no-rebuild`(받은 위치 그대로) | 4.97 cm | 52 | 12.8 | 0.4 GB |
| 다시 쌓기(기본, 작업 스레드) | **2.32 cm** | **48** | 11.5 | 2.6 GB |
| 다시 쌓기, 보관 예산 1500 MB(장면을 하나 걸러 보관) | 2.34 cm | 36 | 11.3 | 1.9 GB |
| 참고: 같은 실행의 끝 그래프 노드 | 2.35 cm | — | — | — |

- 다시 쌓기 5 번(노드 최대 0.5–15.9 cm 움직임), 한 번에 보관 장면 1,108–1,279 개를 5.8–6.4 초(작업 스레드). 그동안 들어온 장면 0–75 개는 갈아 끼울 때 이어 넣는다.
- 지도 위치가 끝 그래프와 같아지고(2.32 대 2.35 cm), 물체 수가 오프라인 기준(48)과 같아졌다. 장면을 하나 걸러 보관하면 위치는 같지만 관측 수가 반이라 물체가 빠진다(칼·꽃병·공 등) → 기본 예산은 3000 MB(640×480 장면 하나 약 1.5 MB + 지도).
- TUM 입력 경로는 바뀌지 않음: fr1 책상을 고치기 전·후 memmap 으로 돌려 물체 목록·`poses_map.txt`·`map.pgm`·표면 면 파일 61 개가 바이트 단위로 같다.

## 깊이 정렬 바꿔 끼우기

깊이를 컬러 격자로 옮기는 곳은 `bridge/src/depth_align.cpp` 하나다. `DepthAligner::align(const rs2::frameset&) → cv::Mat(CV_16UC1, 컬러 크기)` 를 구현한 클래스를 `make_aligner` 에 이름으로 더하고 `--align <이름>` 으로 고른다. 지금은 `rs2`(librealsense `rs2::align`, CPU).
