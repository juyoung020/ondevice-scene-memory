# 계획

작성 2026-10-28 (9주차). 발표는 15주차.

## 목표

손으로 움직이는 RGB 카메라 하나로, 보드 안에서 끝까지(카메라 → NPU 추론 → 3D 매핑 → 씬그래프 → 검색) 물체 공간 기억을 만든다.

## 부품별 결정

| 단계 | 방법 | 돌리는 곳 |
|---|---|---|
| 카메라 위치 추적 | ORB-SLAM3 단안 모드. 실제 크기(m)는 깊이 모델 값과 SLAM 지도 점의 비율을 맞춰 정함. 흔들리면 시작할 때 책상에 ArUco 마커 1장 | Pi5 CPU |
| 물체 분할 | YOLO-seg, 우리가 찍은 데이터로 학습 (물체 종류 10~20개 고정) | NPU |
| 깊이 | 실내용 미터 단위 단안 깊이 모델 (Depth Anything 계열, 변환 안 되면 CNN 계열로) | NPU |
| 물체 벡터 | CLIP 계열 영상 인코더, 물체 부분만 잘라 512차원 1개 (DEEPX 모델 동물원 CLIP 이 1순위 후보) | NPU |
| 글 검색 벡터 | 같은 CLIP 의 글 인코더 | CPU (질의 때만) |
| 3D 매핑 | 마스크 픽셀 × 깊이 → 3D 점, 물체당 약 200점으로 줄임. 3D 겹침 + 벡터 코사인으로 같은 물체 합치기 | CPU |
| 저장 | SQLite 1개 | CPU |
| 보기 | 웹 뷰어 (Pi 가 띄우고 노트북 브라우저로 봄) | CPU |

NPU 모델은 매 프레임이 아니라 **키프레임(초당 2~5장)에만** 돌린다. 이게 경량화의 핵심이다.

코드는 파이썬(DX 런타임 파이썬 API + OpenCV + numpy)으로 먼저 끝까지 잇고, 측정해서 느린 단계만 C++ 로 바꾼다.

## 씬그래프

| 층 | 담는 것 |
|---|---|
| 물체 노드 | id, 클래스, 3D 중심·박스, 대표 벡터(512차원, 볼 때마다 평균), 본 횟수, 마지막으로 본 시각, 썸네일 1장 |
| 관계 선 | 위에 / 안에 / 옆에 — 박스 위치로 기하 계산 |
| 키프레임 노드 | 카메라 위치, 시각, 그때 보인 물체 id |

물체 하나 ≈ 15 KB → 1000개 ≈ 15 MB.

## 질의 (LLM 없음)

- 글: "텀블러" → 글 벡터 → 코사인 top-k → 좌표 + 관계 문장 + 썸네일 + 마지막 본 시각
- 공간: "책상 위 물체" → 관계 선 따라감
- 뷰어: 3D 지도 위 물체를 누르면 위 정보

## 잴 것

| 항목 | 방법 |
|---|---|
| 물체 위치 오차 (cm) | 줄자로 잰 실제 위치와 비교 |
| 놓친 물체 / 중복 노드 수 | 장면마다 실제 물체 목록과 비교 |
| 검색 top-1 / top-5 정답률 | 질의 목록 고정 |
| 단계별 ms, 전체 FPS | Sync vs Async |
| 양자화 손실 | PC FP32 mAP vs NPU INT8 mAP (같은 검증셋) |
| 모델 크기 | `.onnx` vs `.dxnn` |
| 장시간 구동 | 10분 연속, 온도·FPS (`dxtop`) |

## 역할

- A (모델·컴파일러): YOLO-seg 학습, 모델 3개 변환, INT8 보정, 양자화 손실 측정
- B (보드·앱): 카메라, 위치 추적, Async 실행기, 3D 매핑·씬그래프, 검색, 뷰어, 속도 측정

## 위험

| 위험 | 대응 |
|---|---|
| 깊이 모델(트랜스포머)이 DX 컴파일러에서 안 됨 | 10주차에 제일 먼저 시험, 안 되면 CNN 계열 깊이 모델 |
| 단안 SLAM 이 손떨림·빠른 회전에 끊김 | 천천히 훑는 촬영 규칙, 끊기면 재초기화 |
| 깊이 모델 크기 비율이 프레임마다 흔들려 물체가 번짐 | 프레임마다 SLAM 점에 비율 맞춤, 안 되면 마커 |
| Pi5 CPU 가 SLAM + 매핑으로 꽉 참 | 키프레임 수 줄이기, 느린 단계 C++ |
