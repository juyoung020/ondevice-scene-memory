# 연결 프로그램: RTAB-Map → memmap 장면 스트림

`bridge/`(C++, CMake)의 `rtab_bridge` 가 RGB-D 입력을 RTAB-Map 에 넣어 장면마다 위치를 구하고, 위치 + 컬러 + 컬러에 맞춘 깊이를 memmap 으로 흘려보낸다. memmap 은 `--stream` 으로 받아 지금의 TUM·카메라 입력과 같은 지도·물체·씬그래프 단계를 돈다.

```
RealSense D435 (컬러 RGB8 + 깊이 Z16, 640×480@30)      TUM 폴더 재생(rgb.txt·depth.txt, 시험용)
        │ 깊이 → 컬러 정렬(depth_align.cpp, rs2::align)          │
        └──────────────┬───────────────────────────────────┘
                       ▼
     RTAB-Map 위치 추적(매 장, Odometry) + 지도 갱신(Rtabmap::process, DetectionRate 1/초)
                       │ 장면 위치 = 지도 보정 × 위치 추적 × 광학 축
                       ▼  쓰기 스레드(큐, 밀리면 버림 또는 기다림)
           표준출력·파일·이름 있는 파이프 ──→ memmap --stream -  (분할 → 표면·물체·씬그래프)
```

처리 순서(위치 추적 → 놓침이면 새 지도 → DetectionRate 로 지도 노드 고르기 → `Rtabmap::process`)는 RTAB-Map 의 `rtabmap-rgbd_dataset` 도구와 같다. 오프라인 위치 파일(`--gt`)도 이 도구로 만들었다.

## 쓰는 법

```bash
# 빌드(WSL·보드): RTAB-Map·librealsense 설치 경로를 알려 줌. librealsense 가 없으면 TUM 재생만 들어감
cmake -S bridge -B ~/build/bridge -G Ninja -DCMAKE_PREFIX_PATH="$HOME/opt/rtabmap;$HOME/opt/librealsense"
ninja -C ~/build/bridge

# 카메라 → memmap(실시간)
rtab_bridge --realsense --config docs/rtabmap_pi.ini --send-every 2 \
  | memmap --stream - --every 1 --live 1 --surface --seg <분할 모델> --max-depth 3.5 --out data/memory/live

# TUM 재생(카메라 없이): --rate 1 이면 찍은 시각대로(밀리면 건너뜀), 생략하면 최대 속도로 빠짐없이
rtab_bridge --tum data/d435/rgbd_dataset_freiburg3_office_sync --config docs/rtabmap_pi.ini \
  | memmap --stream - --every 2 --surface --seg models/yolo26s-seg.onnx --max-depth 3.5 --out data/memory/office_stream
```

| `rtab_bridge` 인자 | 뜻 |
|---|---|
| `--realsense [--align rs2] [--serial S] [--size 640x480] [--fps 30]` | RealSense 입력(IMU 는 켜지 않음) |
| `--tum <폴더> [--rate R]` | TUM 폴더 재생. 보정값은 memmap `tum.rs` 와 같이 폴더 이름으로(freiburg1·2·3) |
| `--config <ini>` | RTAB-Map 설정(`[Core]`), 그 뒤 `--Group/Name 값` 으로 덮어씀 |
| `--out -\|<파일>` | 스트림 출력(기본 표준출력). 파일로 남겨 두면 `memmap --stream <파일>` 로 다시 돌릴 수 있음 |
| `--send-every N` | N 장마다 보냄(위치 추적은 모든 장면) |
| `--queue N`, `--block`·`--drop` | 쓰기 큐 길이(기본 4), 큐가 차면 기다림·가장 오래된 장면 버림. 기본은 최대 속도 재생 = 기다림, 카메라·`--rate` = 버림 |
| `--poses <파일>` | 보낸 위치(TUM 형식, OpenCV 카메라 → RTAB-Map 지도) |
| `--final-poses <파일>` | 끝에 최적화된 지도 노드 위치(TUM 형식, 같은 좌표) |
| `--stats <파일>` | 장면별 시간·놓침·새 지도·지도 보정·특징 수(CSV) |
| `--db <파일>` | RTAB-Map 데이터베이스로 남김(`rtabmap-databaseViewer` 로 볼 수 있음) |

RTAB-Map 로그는 표준오류로 나간다(표준출력은 시작할 때 떼어 스트림 전용으로 쓴다).

| `memmap` 인자 | 뜻 |
|---|---|
| `--stream -\|<파일>` | 장면 스트림 입력. 위치·깊이는 받은 그대로, 분할은 memmap 이 돌림. `--every N` 은 받은 장면 N 장마다 |
| `--no-level` | 받은 위치의 z 를 그대로 위로 씀(기본은 아래 "바닥 맞추기") |
| `--rebuild-every S`, `--kf-store-mb M`, `--no-rebuild` | 루프 클로저 뒤 다시 쌓기 간격(초, 기본 5, 0 = 끝에만)·장면 보관 예산(MB, 기본 3000)·끄기(아래 "루프 클로저 뒤 다시 쌓기") |
| `--submap-secs S`, `--submap-m M`, `--submap-deg D` | 표면 서브맵을 새로 여는 시간·거리·각도(기본 20 초·2 m·60°) |
| `--tex-mb M`, `--no-texture` | 표면 텍스처용 사진 보관 예산(MB, 기본 400)·끄기(아래 "표면 텍스처") |

memmap 출력은 TUM 입력과 같고, 스트림이면 `poses_est.txt`(받아 쓴 위치, 수평 맞춘 세계)가 더 생긴다. 모든 입력에서 `poses_map.txt`(지도에 넣은 장면의 카메라 위치, 메쉬 좌표)가 생긴다.

## 스트림 형식

장면 하나 = 머리 176 바이트 + RGB8(`w×h×3`, 행 우선, R·G·B) + 깊이(`w×h` 개 u16). 장면 사이에 그래프 블록(아래)이 끼어 온다. 모든 수는 리틀 엔디언, 실수는 IEEE 754. 보내는 쪽이 닫으면 끝.

| 위치 | 형 | 칸 | 값 |
|---|---|---|---|
| 0 | char[4] | 표시 | `MMF1` |
| 4 | u32 | 머리 크기 | 176 |
| 8 | u32 | 상태 | 1 = 위치 놓침(위치 칸 무시), 2 = 이 장면에서 새 지도 시작, 4 = 이 장면에서 지도 보정(루프 클로저·최적화)이 바뀜 |
| 12 | u32 | 지도 번호 | RTAB-Map 지도 번호(새 지도마다 늘어남) |
| 16 | u64 | 장면 번호 | 입력 순서(보내지 않은 장면도 셈) |
| 24 | f64 | 시각 | 초(TUM: 파일 시각, RealSense: 컬러 장면 시각) |
| 32 | f64[12] | 위치 | 3×4 행 우선 `[R | t]`: OpenCV 카메라 → 세계 |
| 128 | f64[4] | 보정값 | fx, fy, cx, cy(컬러, 왜곡 없음) |
| 160 | u32 ×2 | 크기 | w, h |
| 168 | f32 | 깊이 배율 | 깊이 값 / 미터(RealSense 1000 = mm, TUM 5000). 0 = 깊이 없음 |
| 172 | u32 | 기준 노드 | 이 장면의 기준 RTAB-Map 지도 노드 id(`getLastLocationId()`, 0 = 없음). 장면 위치 = 그 노드 위치 × 상대 위치 |

그래프 블록 = 머리 16 바이트 + 노드마다 104 바이트. 지도 갱신(`Rtabmap::process`) 뒤 새로 생기거나 움직인(3×4 행렬 원소가 1e-3 넘게 바뀐) 노드만 담아 그 장면보다 먼저 보낸다. 쓰기 큐가 차도 버리지 않는다.

| 위치 | 형 | 칸 | 값 |
|---|---|---|---|
| 0 | char[4] | 표시 | `MMG1` |
| 4 | u32 | 머리 크기 | 16 |
| 8 | u32 | 노드 수 | n |
| 12 | u32 | 예약 | 0 |
| 16 + 104·i | u32, u32 | 노드 id, 예약 | `getLocalOptimizedPoses()` 의 id, 0 |
| 24 + 104·i | f64[12] | 노드 위치 | 3×4 행 우선, OpenCV 카메라 → 세계(장면 위치와 같은 좌표: 노드 위치 × opticalRotation) |

깊이는 컬러 화소 격자에 맞춘 것. memmap 은 `값 / 깊이 배율` 로 미터를 만든다(TUM 입력 `tum.rs` 와 같은 계산이라 같은 영상이면 같은 수).

## 좌표 약속

| | 카메라 축 | 세계 축 |
|---|---|---|
| memmap(`r`, `p`) | OpenCV: x 오른쪽, y 아래, z 앞 | x·y 수평, **z 위**(바닥·점유 지도·방 나누기가 z 를 위로 씀) |
| RTAB-Map 위치 추적 | 몸체: x 앞, y 왼쪽, z 위(ROS) | 지도: 첫 장면의 몸체 축(IMU 없으면 z 는 처음 든 카메라의 위) |
| 몸체 → 광학 축 | `CameraModel::opticalRotation()` = `[[0,0,1],[-1,0,0],[0,-1,0]]`(열 = 광학 x·y·z 를 몸체로) | |

- 연결 프로그램이 보내는 위치 = `지도 보정 × 위치 추적 × opticalRotation`. 첫 장면은 정확히 `opticalRotation` 이 되고, 이것은 memmap 웹캠 입력의 첫 자세(`r0 = [[0,0,1],[-1,0,0],[0,-1,0]]`, 수평으로 앞을 봄)와 같다. 그래서 회전을 따로 바꾸지 않는다.
- **바닥 맞추기**: RTAB-Map 지도의 z 는 첫 장면 카메라가 기운 만큼 기울어 있다. memmap 은 웹캠 입력과 같은 방법(장면마다 RANSAC 으로 찾은 수평면 법선 15 개 이상이 10° 안에서 합의)으로 위쪽을 정해 그 뒤 오는 모든 위치에 같은 회전을 곱한다. 합의 전 장면은 지도에 넣지 않는다.
- 높이: memmap 이 첫 장면의 바닥 높이(카메라 아래 깊이 점 95 %)로 원점을 바닥에 맞춘다(TUM 입력과 같음).
- 코드로 확인한 것(검증 표의 `자세 차이`): 보낸 위치를 정답에 맞춘 뒤 카메라 자세 차이가 사무실 1–2°, 책상 3–6°. 몸체 축을 그대로 보냈다면 opticalRotation 의 회전각인 120° 가 나온다. memmap 이 받아 쓴 위치(`poses_est.txt`)를 보낸 위치에 맞추면 위치 차이 0, 자세 차이 0°(바닥 맞추기 회전 한 번만 다름).

## 놓침·새 지도·루프 클로저

- 위치를 못 구한 장면은 상태 1 로 보내고 memmap 은 지도·물체에 넣지 않는다(개수는 결과 JSON `stream_lost`).
- `Odom/ResetCountdown 1` 이면 놓친 다음 장면에서 위치 추적이 마지막 위치로 다시 시작하고, 연결 프로그램은 `triggerNewMap()` 으로 새 지도를 연다(도구와 같음). 그 장면은 위치가 "마지막 위치"로 채워질 뿐이라 놓침 + 새 지도(1 + 2)로 보낸다. 이후 장면은 새 지도에서 이어지고, 옛 지도와 루프가 닫히면 RTAB-Map 이 두 지도를 한 좌표로 합친다.
- 루프 클로저로 지도 보정이 바뀌면 그 장면부터 위치가 보정된 좌표로 오고(상태 4), 그 앞에 움직인 노드를 담은 그래프 블록이 온다.

### 루프 클로저 뒤 다시 쌓기(memmap)

- memmap 은 지도에 넣은 장면을 기준 노드와 그 노드에서 본 상대 위치로 보관한다(`kfstore.rs`). 상대 위치는 받을 때 `기준 노드 위치⁻¹ × 장면 위치` 로 구한다. RTAB-Map 에서 마지막 노드 위치 = 지도 보정 × 그 노드의 오도메트리 위치라, 이 값은 오도메트리 상대 움직임과 같고 루프 클로저로 바뀌지 않는다.
- **표면(`--surface`)은 서브맵**(`submap.rs`, Voxblox·voxgraph·cblox 방식): 장면을 짧은 구간의 TSDF(서브맵)에 쌓고 서브맵을 RTAB-Map 노드에 붙인다. 서브맵 좌표는 만들 때 지도 좌표와 같은 방향이고 원점은 카메라 위치를 블록 격자(24 cm)에 맞춘 곳이라, 자세가 그대로인 서브맵은 칸이 전체 표면 칸과 겹쳐 보간 없이 더해진다. 서브맵 자세 = 기준 노드의 지금 위치 × 만들 때 정한 상대 위치.
  - 새 서브맵: 장면의 기준 노드가 바뀌었고 지금 서브맵이 `--submap-secs`(기본 20 초)를 넘었거나 카메라가 `--submap-m`(2 m)·`--submap-deg`(60°) 넘게 움직였을 때. 다시 합치기를 시작할 때와 쌓는 서브맵의 노드가 움직였을 때도 새로 연다.
  - 전체 표면 = 서브맵마다 지금 자세로 옮겨 무게 평균(cblox `getProjectedMap`). 옮길 때는 전체 표면 칸 중심을 서브맵 좌표로 되돌려 이웃 8 칸을 삼선형 보간하고(빈 칸은 무게 0), 블록 단위 이동이면 칸을 그대로 옮긴다. 쌓는 중인 서브맵은 면 파일을 쓰기 전에 바뀐 블록만 옮긴다(지난번 옮긴 값을 빼고 지금 값을 더함).
  - 그래프 블록 뒤 서브맵 자세가 2 cm 또는 1° 넘게 바뀌었으면 작업 스레드가 다 쌓은 서브맵을 새 자세로 빈 전체 표면에 합치고, 본 스레드가 갈아 끼우며 그동안 생긴 서브맵을 더한다. 판 번호는 이어받고 움직인 서브맵이 덮던 구역·덮는 구역만 면 파일을 다시 쓴다. 실행 번호는 그대로라 뷰어는 바뀐 구역만 받는다.
- **점유 지도·물체·지나온 길**: 같은 문턱으로 `--rebuild-every` 초(기본 5)에 한 번까지 작업 스레드가 비우고 보관한 장면을 `지금 노드 위치 × 상대 위치` 로 처음부터 다시 쌓는다(실시간 장면과 같은 `map_frame`, 물체 병합 후처리는 15 장마다). 스트림이 끝났을 때 표시가 남아 있으면 한 번 더 쌓아 결과 지도·물체·`poses_map.txt` 가 끝난 그래프를 따른다. 물체 id 는 이어서 쓴다.
- 표면 지도의 장면 보관은 줄인 형태: 깊이는 4 화소 간격, 검출 상자 안은 컬러·깊이 그대로(손실 없는 압축, 줄 안 차분 + LZ4), 장당 약 0.45 MB. 점유 지도는 16 화소 간격(8 + 16k) 깊이만 읽어 받은 값과 같고, 물체 점·사진은 상자 안만 읽는다. 사라짐 판정(보여야 할 자리의 깊이)만 4 화소 간격 깊이를 쓴다. 점 지도를 만들면(`--surface` 없음 또는 `--points`) 장면 전체(약 0.85 MB)를 보관해 점 지도까지 다시 쌓는다.
- 보관 예산 `--kf-store-mb`(기본 3000): 넘으면 보관한 장면을 하나 걸러 버리고 이후 두 배 간격으로 보관한다. `--rebuild-every 0` 은 끝에만, `--no-rebuild` 는 보관·서브맵·다시 쌓기 없이 받은 위치 그대로 쌓는다.
- 기준 노드를 모르는 장면(노드가 생기기 전, 다른 지도에서 끊긴 노드)은 받은 위치 그대로 쌓는다.

### 3D 점 지도(옥트리 LOD, memmap `maps.rs`, 뷰어)

`--surface` 가 없으면 늘, `--surface --points` 면 표면 지도와 함께 점 지도를 만든다(Potree 방식으로 보여 줌).

- **점 고르기**: 장면마다 `--scene-step`(기본 2) 화소 간격으로 깊이 점을 만들되 깊이 경계(5×5 에서 8 % 넘게 들쭉날쭉)와 비스듬히 본 면(이웃 ±2 화소로 만든 법선과 시선의 코사인 0.3 미만)을 빼고 `--pts-depth`(기본 3 m) 안만 쓴다. 점은 `--scene-vox` 칸(시연 0.006 m)에 모아 칸 안 평균 위치로, 색은 가장 가까운 거리의 2 배 안에서 본 관측의 평균. 칸을 본 키프레임이 `--pts-obs`(기본 3) 장에 닿으면 점이 된다(한두 장에만 맞은 잡음 점은 남지 않음). 칸 하나 14 바이트.
- **옥트리**: 수준 L(0–5)의 점 간격 = 칸 × 2^(5−L), 노드 한 변 = 간격 × 32. 새 점은 자기 칸이 아직 빈 가장 굵은 수준의 노드 하나에만 들어간다(겹침 없음, Potree 와 같이 부모가 성기게 전체를 덮고 자식이 촘촘함을 더함).
- **파일**: `scene/<판>/n<L>_<x>_<y>_<z>.bin`(점마다 노드 상자 안 u16 × 3 위치, 그 뒤 RGB — 점당 9 바이트, 뷰어가 해석 없이 그대로 올림)과 노드 목록 `scene/<판>/octree.json`(`[수준, x, y, z, 점 수, 판]`). `view.json` 의 `scene_points.octree` 에 판·목록 판 번호가 들어간다.
- **늘려 쓰기**: 1 초(실시간)마다 새 점을 노드에 넣고, 점이 처음 생겼거나 10 % 넘게 는 노드만 다시 쓴다. 한 번에 다시 쓰는 점은 30 만 개까지(넘는 노드는 다음 번), 끝에는 남은 노드를 모두 쓴다.
- **루프 클로저**: 다시 쌓기 작업 스레드가 점 지도도 처음부터 쌓고 모든 노드 파일 바이트까지 만든다. 본 스레드는 갈아 끼우며 새 판 폴더에 쓰고 옛 판 폴더를 지운다. 판 번호가 바뀌면 뷰어는 받은 노드를 비우고 새로 받는다.

검증(WSL, 사무실 녹화 스트림, `--depth kinect --seg yolo26s-seg.onnx --every 2 --max-depth 3.5 --scene-vox 0.006`, 2026-11-08): 점 4.53 M(예전 0.005 m 네모 점 13.9 M · 199 MB → 노드 1,550 개 43 MB), 지도 넣기 22 ms/장, 노드 쓰기 한 번 60–170 ms(장면 50 장 몫, 실시간 1 초 몫은 그 약 1/7), 점 지도 메모리 약 400 MB(최대 RSS 3.2 GB 중 보관 장면 1.3 GB), 다시 쌓기 작업 스레드 11–31 초. 물체·위치는 점 지도와 무관하게 같다(fr1_desk TUM 입력 main 과 물체 목록 일치). 그림: `docs/results/potree_before_*.png` → `potree_after_*.png`(Low: `potree_after_low.png`, 0.8 M 점), 같은 시점 표면 지도 `potree_mesh_*.png`, Potree 예제 `potree_reference.png`. 먼 시점은 Potree 처럼 촘촘하고 윤곽이 서지만, 가까이서는 Kinect 깊이 잡음으로 점이 알갱이처럼 보이고 책상 글자는 읽히지 않는다 — 이 데이터에서는 텍스처 표면 지도가 더 선명해 표면이 기본으로 남는다.

### 표면 텍스처(memmap `texture.rs`, 뷰어)

스트림 표면 지도(`--surface`, 서브맵)는 구역 면에 장면 사진을 붙인다(Open3D color map·mvs-texturing 을 줄인 방식). `--tex-mb M`(기본 400)이 사진 보관 예산, `--no-texture` 는 색 면만.

- **사진 보관**: 지도에 넣은 장면마다 선명도(절반 크기 회색의 라플라시안 분산)를 재고, 비슷한 자리(12 cm·12° 안)에 보관한 사진이 없거나 그보다 10 % 넘게 선명할 때만 JPEG(품질 90) + 4 화소 간격 깊이로 보관한다. 위치는 장면 보관과 같은 기준 노드 × 상대 위치라 루프 클로저를 따른다. 예산을 넘으면 가까운 이웃이 있는 사진 중 가장 흐린 것부터 버린다.
- **고르기**: 구역마다 구역을 담는 사진 24 장을 후보로, 삼각형마다 법선 쪽에서 본 사진 중 `cos / 거리² × √(선명도 / 중앙값)`(가장자리 감점) 이 높은 6 장을 남긴다. 세 꼭짓점이 사진 가장자리 6 화소 안이고 보관 깊이와 맞아야(가려짐) 하며, 깊이 경계(이웃 3×3 칸에 빈 값 또는 15 % 넘는 깊이 차)는 뺀다. ICM 6 번(점수 손해 + 이웃과 다른 수 × 1.0)으로 이웃끼리 같은 사진을 쓰게 다듬는다.
- **아틀라스**: 같은 사진 삼각형 덩어리(차트)마다 사진 조각을 둘레 2 화소 여백과 함께 잘라 구역 아틀라스 한 장(선반 쌓기, 한 변 최대 1024, 넘치면 줄임)에 모은다. 사진이 없는 삼각형은 흰 칸 + 표면 색.
- **노출 맞춤**: 꼭짓점마다 표면 색(모든 장면 평균) ÷ 사진 색(5×5 흐린 값)을 차트 안 이웃끼리 세 번 평균해 꼭짓점 색(0.7–1.4 배, ÷ 2 로 저장)에 둔다. 그릴 색 = 아틀라스 × 꼭짓점 색 × 2 라 차트 경계 양쪽이 같은 표면 색에 맞아 이음매가 줄고 안쪽 무늬는 사진 그대로다.
- **이음매 섞기**: 차트 경계에 닿은 삼각형만 여러 사진을 섞는다. 꼭짓점마다 사진 무게 = 둘레 삼각형 중 그 사진 삼각형의 비율이라 경계 꼭짓점은 양쪽 차트에서 같은 무게를 갖고, 무게를 삼각형 안에서 보간해 삼각형 한 개 폭 안에서 이웃 사진으로 넘어간다. 이웃 사진 색은 (그 사진 노출 배율 ÷ 이 차트 배율)로 맞추고, 그 사진에서 가려진 점(보관 깊이와 안 맞음)은 섞지 않는다. 그림: meshshot `docs/results/texture_seam_before.png` → `texture_seam_after.png`(상자 앞면·책상의 조각난 밝기 차가 이어짐), 뷰어 `texture_seam_after_viewer.png`. 구역 붙이기 평균 29 → 37 ms·최대 0.40 → 0.43 초(PC 코어 2 개, 작업 스레드).
- **출력**: `mesh/t_x_y_z_n.ply`(위치·법선·UV `s t`·색) + `mesh/t_x_y_z_n.jpg`(품질 85), n = 구역 텍스처 번호. view.json 표면 목록은 지금 면에 붙인 구역만 `[x, y, z, 판 번호, n]`, 나머지는 `[x, y, z, 판 번호]`(색 면 `r_x_y_z.ply`). 색 면 파일은 늘 같이 쓴다.
- **작업 스레드**: 본 스레드는 장면(컬러 복사 + 4 화소 간격 깊이)·그래프·바뀐 구역 면을 넘기기만 한다(장면 큐 8 장, 밀리면 버림). 작업 스레드는 2 초 넘게 안 바뀐 구역부터(붙인 적 없는 구역 먼저) 하나씩 붙이고 걸린 만큼 쉰다(코어 하나의 절반). 다시 붙이는 때: 면 판 번호가 바뀜, 쓴 사진이 바뀌어 넣어짐, 쓴 사진 위치가 1 cm·0.5° 넘게 움직임(루프 클로저). 스트림이 끝나면 남은 구역을 코어 여럿으로 모두 붙인 뒤 마지막 view.json 을 쓴다.
- **뷰어**: 텍스처 구역은 구역마다 메쉬 하나(아틀라스 텍스처, 이방성 4), 색 구역은 블록 묶음. 표면 셰이더 하나(반구 빛 0.55–0.85 + 해 빛 0.25, 꼭짓점 법선, 양면)로 그리고 화면 후처리는 없다. "Surface shading" 을 끄면 사진 색 그대로. `?cam=ex,ey,ez,tx,ty,tz` 로 처음 시점을 정한다(시험·시연).

검증(WSL, 사무실 녹화 스트림, `--depth kinect --surface --seg yolo26s-seg.onnx --every 2 --max-depth 3.5`, 2026-11-08):

## 검증 (WSL Ubuntu 24.04, TUM 재생, 2026-11-05)

`bridge/tools/check_tum.sh` 로 시퀀스마다 세 번 돌려 견줌. 이 표는 RTAB-Map 0.24.2 를 Ubuntu 패키지(OpenCV 4.6 xfeatures2d 없음, g2o)로 빌드한 GFTT/ORB · g2o 조합으로 잰 것이다. 지금 ini 의 GFTT/BRIEF · GTSAM 과의 비교는 아래 "특징·최적화기 비교". memmap 은 ONNX Runtime CPU 로 YOLO26s-seg 분할, `--depth kinect --surface --every 2`, 최대 거리 사무실·책상 3.5 m, 복도 4 m.

- **기준**: 같은 설정 + 모든 장면을 지도 노드로 끝까지 돌려 최적화한 위치 → `memmap --tum --gt`(오프라인 경로).
- **같은 위치 오프라인**: 스트림 실행이 보낸 위치 파일 그대로 → `memmap --tum --gt`. 스트림과 위치가 같고 입력 경로만 다르다.
- **스트림**: `rtab_bridge | memmap --stream -`(보드와 같은 설정, 장면이 들어올 때의 위치).

- 지도(사무실 녹화 스트림 → memmap `--depth kinect --surface --seg yolo26s-seg.onnx --every 2 --max-depth 3.5`, `data/memory/q_bg`): 지도 위치(`poses_map.txt`) 오차 7.50 → **2.81 cm**, 물체 49 → 48, 루프 클로저 12, 걸린 시간 1:45, 최대 메모리 1.52 GB. 그림(뷰어 같은 시점, 이전 = ORB + g2o): `docs/results/briefgtsam_v_before_desk.png` → `briefgtsam_v_after_desk.png`, 가까이 `briefgtsam_v_before_close.png` → `briefgtsam_v_after_close.png`. 테이프 받침(빨강)이 두 겹 조각에서 한 덩어리로, 잡지 글자가 조금 더 또렷해진다. 칸막이 둘레 깊이 경계의 잘게 쪼개진 조각, 비닐봉지·접시의 번짐, 반사 얼룩은 둘 다 남는다(위치보다 텍스처 고르기 쪽 원인).
- 정확도 우선은 사무실 1.9–2.0 cm 로 가장 정확하지만 장면당 약 3 ms 더 들어 보드(장당 27–30 ms)에서 30 장/초를 넘는다. 15 장/초 입력이나 정확도가 먼저인 녹화 재생에 쓴다.

### 루프 클로저 뒤 다시 쌓기 검증 (WSL, 2026-11-08)

사무실 2,585 장을 `rtab_bridge --config docs/rtabmap_pi.ini --out <파일>` 로 녹화한 스트림 파일 하나로 memmap(`--depth kinect --surface --seg yolo26s-seg.onnx --every 2 --max-depth 3.5`)을 돌려 견줌. 장면 하나씩 다시 넣는 방식(모든 장면으로 표면까지 다시 쌓기)이 기준. 위치 오차는 `poses_map.txt` 의 `ate`(정답 기준, 이 녹화의 끝 그래프 위치라 두 방식이 같음), 표면은 `surfcmp --align`(서브맵 → 기준).

- 서브맵 16 개 80 MB + 전체 표면 21 MB, 보관 장면 1,279 개 577 MB(전체 보관이면 약 1.1 GB). 다시 합칠 때 움직인 서브맵 6–13 개, 다시 쓴 구역 22–129 개.

## 깊이 정렬 바꿔 끼우기

깊이를 컬러 격자로 옮기는 곳은 `bridge/src/depth_align.cpp` 하나다. `DepthAligner::align(const rs2::frameset&) → cv::Mat(CV_16UC1, 컬러 크기)` 를 구현한 클래스를 `make_aligner` 에 이름으로 더하고 `--align <이름>` 으로 고른다. 지금은 `rs2`(librealsense `rs2::align`, CPU).
