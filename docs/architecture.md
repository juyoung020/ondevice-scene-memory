# 동작 원리

## 처리 흐름

```
ondevice — 한 프로세스(위치 · 물체 기억 · 뷰어 서버)

RealSense D435 (컬러 + 깊이, 640×480@30)
        ▼ 위치 프로그램 (처리 루프, RTAB-Map 0.24.2 경로를 옮김)
  장면마다 위치 추적(F2F), 루프 클로저로 지도 노드 위치 다시 맞춤(BRIEF + GTSAM 방식)
  → 장면(컬러 + 컬러에 맞춘 깊이 + 위치 + 기준 노드) · 그래프 블록(움직인 노드)을 같은 루프의 줄로(복사 없이)
        ▼ 물체 기억 (memmap)
  NPU 분할 (ObjectSAM, 이름 없는 물체) → 물체 마스크
  NPU SigLIP2 사진 벡터 → 실내 낱말 표(vocab/indoor.voc)에서 가장 닮은 이름
  점 지도(점 줄, 작업 풀): Potree 방식 옥트리 노드
  점유 지도: 바닥 5 cm 칸
  검출 거르기: 화면 가장자리 셋에 잘린 마스크 · 6 cm 안 조각 · 가는 조각 · 바닥/천장 면은 물체로 넣지 않음
  물체 트래커: 같은 자리·같은 이름이면 같은 물체로 합침, 안 보이면 "사라짐", 몇 번만 보였고 점수가 낮은 이름 없는 물체는 지움
  병합 후처리(15 장마다): 따로 생긴 두 물체를 3D IoU·겹침 비율·이름 분포·색 분포·사진 벡터로 판단해 합침
  물체 사진 벡터(--embed, 사진 벡터 줄 + NPU): 물체의 가장 좋은 사진 → SigLIP2 영상 인코더 → 768 차원 벡터
  루프 클로저 뒤 다시 쌓기(다시 쌓기 줄, 작업 풀): 보관한 장면으로 점유 지도·점 지도·물체를 새 위치로
        ▼
  씬그래프: 방 나누기(Hydra room finder 의 2D 판 — 벽까지 여유가 큰 곳부터 채워 가며 문처럼 좁은 목에서 끊음. 벽은 높이 1.3 m 넘는 막힘만 — 책상·의자는 방 안으로 본다) → 방→물체, 방↔방(문), 물체 위·옆 관계
  방 이름: 방 안 물체 이름으로 종류별 점수 → 확률·근거(예: 노트북·키보드·마우스 → office), 같은 종류는 번호(kitchen 2), 방 번호는 지도가 자라도 유지
        ▼
  기억 폴더(view.json · 점 노드 · 물체 사진 · 물체 벡터) — --serve 면 메모리(memfs)에 두고 끝에 디스크로
        ▼ 뷰어 서버 (처리 루프 epoll) → 웹 뷰어(바뀐 몫만 이진으로 밀어 줌 /bstream, 검색어 → SigLIP2 글 인코더 → 물체 순위)
```

- 명령줄은 시작할 때 한 번 읽어 위치(`--slam "…"`) · 물체 기억 · 뷰어(`--serve "…"`) 설정으로 나눈다(`common::cli`). 잘못된 인자는 장치를 열기 전에 멈춘다.
- 스레드는 처리 루프 하나 + IMU 읽기 하나(IMU 모드) + 작업 풀(`--pool N`, 기본 3)뿐이다. 루프는 epoll 하나에 카메라 장치 fd · 뷰어 소켓 · 깨우개(NPU 끝 · 풀 일 끝 · IMU 표본 · 뷰어 버튼)를 걸고 잠들었다가 준비된 일을 한다. 배치(`--threads`): 루프는 본 스레드 역할(nice · 코어), 풀은 점 역할 코어(nice 0, 긴 줄 일은 그 일 동안만 nice 10). 구조 · 넘김 · 복사 표는 [threads_npu.md](threads_npu.md).
- PC 빌드의 .onnx 모델(분할 · 사진 벡터 · MegaLoc · XFeat)은 Rust 실행기 `common::nn` 하나가 돌린다(그래프 읽기 · 상수 접기 · 묶기 · 판 행렬곱, 일꾼 묶음 하나를 모델마다 상한을 두고 나눠 씀). 보드 빌드는 NPU(DXRT), 뷰어 검색 글 인코더는 어디서나 Rust(`viewer/sgview/src/textnet.rs`). 대조 기록은 [ort_port.md](ort_port.md).
- 뷰어 서버는 이 프로세스가 만든 파일을 메모리에서 보낸다(`sgview::memfs`, view 는 `sgview::live`). 디스크에서 읽는 것은 따로 띄운 뷰어(`ondevice view`)뿐이다.
- 처리가 0.2 s 넘게 밀리면 쌓인 장면을 건너뛰고 최신 장면부터 처리한다. 그래프 블록은 버리지 않는다(`--no-drop` 이면 모두 처리).
- 분할 모델은 공통 인터페이스(`Segmenter`)로, 모델 파일이 `.onnx` 면 PC(Rust 실행기), `.dxnn` 이면 보드 NPU(DXRT C API)에서 돈다.
- 분할은 루프가 장면을 전처리해 NPU 에 바로 올리고(DXRT 비동기 실행, 결과는 받을 버퍼에 바로) 끝 알림(`--npu-wake thread` 기다림 스레드 · `callback` DXRT 콜백)이 루프를 깨우면 올린 순서대로 마스크 해독 · 물체 기억까지 한다. 보드 NPU 에는 장면을 `--npu-jobs` 장까지 함께 올리고 장면 순서는 그대로다. NPU 호출 단계는 [threads_npu.md](threads_npu.md).
- 병합 기준(HOV-SG·ConceptGraphs 방식): 4 cm 칸 IoU ≥ 0.5, 또는 작은 쪽 기준 겹침 ≥ 0.6 이면서 이름 투표 코사인 ≥ 0.5 이거나 색 히스토그램 코사인 ≥ 0.8.
- 사진 벡터로 합치기: 두 물체의 사진 벡터 코사인 ≥ 0.88 이고 작은 쪽 굳은 칸의 25 % 이상이 큰 쪽 굳은 칸과 겹치면 이름이 달라도 합친다(같은 물체가 보는 방향에 따라 두 이름으로 남은 경우). 사진 벡터는 물체의 종류까지만 가린다 — 나란히 놓인 모니터 두 대도 코사인이 0.92 다. 그래서 자리가 겹칠 때만 쓰고, 같은 이름의 이웃 물체는 칸 겹침·맞닿음·전형 크기로 가른다. 벡터가 아직 없는 물체는 기하·이름 조건만 본다.
- 물체 사진 벡터: 기록 회차마다 바뀐 물체 사진 묶음을 사진 벡터 줄이 전처리해 NPU 에 `--embed-jobs` 장까지 함께 올리고 `objects/O<id>_emb.bin`(f32 768 개, 길이 1)을 다시 쓴다. 밀리면 물체마다 가장 새 사진만 계산한다. 최대 속도 재생은 다음 기록 회차 앞에서 맡긴 차례대로 반영한다(결과가 늘 같게).
- 검색(`/api/search`, 뷰어 `search.rs`): 검색어 글 벡터 × 물체 사진 벡터 표(`objtable`, 메모리) 한 번 → p = sigmoid(111.83 · cos − 16.77)(SigLIP2 체크포인트 보정값) → p ≥ 0.004(한글 질의 0.0025)인 물체를 코사인 순으로. 물체 이름 글자가 검색어와 겹치면 맨 앞(점수 1). 근거 · 비교는 [search_direct.md](search_direct.md).
- 위치 프로그램은 C++ 원본(RTAB-Map 0.24.2 연결 프로그램)과 PC 에서 출력이 바이트까지 같았다(slam/README.md "검증"). 스트림 형식·루프 클로저·다시 쌓기: [bridge.md](bridge.md), 보드 설치 [board_bridge.md](board_bridge.md).

## 스레드 지도

한 프로세스, 처리 루프 하나가 상태(위치 추적 · 물체 기억 · 격자 · 보관 장면 · 연결)를 모두 가진다. 무거운 뒤 일은 줄(lane)로 작업 풀에 맡기고 끝나면 완료 줄 · 깨우개로 돌아온다(줄 하나는 한 번에 일꾼 하나: 순서 · 결과가 전용 스레드와 같다). 설정은 시작할 때 한 번(`common::cli`), 조종 신호는 하나(`common::control`: 리셋 · 수평 · 저장, 오면 루프를 깨움).

| 자리 | 하는 일 | 깨우는 것 |
|---|---|---|
| 처리 루프(`ondevice`) | 카메라 짝 맞추기 · 위치 추적 · 지도 노드 명령, 분할 전처리 · NPU 올리기 · 받기 · 마스크 해독, 수평 · 바닥 높이 · 점유 격자 · 물체 트래커 · 병합, 장면 사이 위치(IMU), 뷰어 HTTP · 스트림 | 카메라 fd · NPU 끝 · 풀 끝 · IMU 표본 · 소켓 · 마감 |
| IMU 읽기(`imu`, IMU 모드) | I2C 200 Hz 읽기 · 거르기 · 링 | 자기 타이머(SCHED_FIFO 50) |
| 작업 풀(`pool-0` …, `--pool 3`) | 줄: 지도 갱신(`map`) · 키프레임 기술자(`desc`) · 점 지도와 보관 압축(`pts`) · 방 · 판(`view`) · PNG · PLY · 저장(`io`) · 사진 벡터(`embed`) · 다시 쌓기(`rebuild`) · 재생 PNG 풀기(`replay`) · 글 검색, 펼치기(par_iter) | 루프가 일을 넣을 때 |
| NPU 끝 알림(`npu-wait-seg` · `npu-wait-emb`, `--npu-wake thread`) | 모델마다 `dxrt_engine_wait` 만 하고 루프를 깨움(콜백 길이면 없음) | NPU |
| (PC 만) `seg-onnx` | ONNX 분할 실행(NPU 자리) | 올림 |

- `--serve`(한 프로그램): 기억 폴더는 메모리(memfs)에만 두고 장면마다 디스크(보드 SD 카드)를 건드리지 않는다. view 는 구조(물체 · 격자 · 방 · 엣지 값 + 덧붙이기만 하는 길 로그)로 넘기고 JSON 바이트는 브라우저가 물을 때 판마다 한 번 짠다(디스크 view.json 과 같은 바이트). 검색 · 벽 계산은 값을 그대로 읽는다. 실시간이면 받은 장면마다 뷰 판 · 점 노드를 내보낸다(뷰 줄이 바쁘면 마지막 판만, 점 노드는 점 줄이 한가할 때).
- 브라우저는 `/bstream` 한 연결로 받는다. 서버(처리 루프 안, 논블로킹 소켓)는 페이지마다 보낸 판(물체별 해시 · 길 길이 · 지도 판 · 옥트리 노드 판 · 위치 판)을 기억하고, memfs 가 바뀌면(거는 쪽이 루프를 깨움) 그 페이지가 못 받은 것만 한 덩어리로 보낸다(따로 띄운 뷰어는 50 ms 마다 폴더를 봄). 형식: `viewer/sgview/src/delta.rs`.
- 브라우저의 점 지도는 2.5 m 블록마다 큰 GPU 버퍼(13 만 점) 몇 개에 노드를 넣고 바뀐 범위만 올리며(프레임당 예산), 노드 자리 · 보이는지는 노드 표 텍스처 하나로 정한다. 다시 쌓기 · 재생 다시 시작으로 판이 바뀌면 새 판을 뒤에서 올리고 한 프레임에 바꾼 뒤 옛 판 버퍼를 프레임마다 하나씩 새 판에 다시 쓴다.
- 결정적 재생(`--no-drop`, `--seg-cache`)은 모든 단계가 장면을 하나도 건너뛰지 않아 출력이 늘 같다.

### 실시간 단계 모양

```
[카메라 fd] → 루프: 위치 추적 → (분할 차례면) NPU 자리가 나는 대로 가장 새 장면 올림 ──끝 알림──▶ 루프: 마스크 해독 → 지도 · 물체
     │                                                                                             │
     └── 위치를 바로 뷰어로(IMU 모드는 표본마다)                          줄: 점 지도 · 보관 · 뷰 판 · 사진 벡터 · 기록 · 다시 쌓기
```

- 결과를 늘 같게 하는 재생(`--no-drop`, 최대 속도)은 NPU 자리가 빌 때까지 다음 장면을 읽지 않고, 줄 결과를 지금 기다리던 바로 그 자리에서 기다린다(점 노드 쓰기 · 다시 쌓기 갈아 끼우기 · 깊이 정합 · 사진 벡터 회차).
- 실시간은 카메라 장면을 모두 위치 추적에 넣고, 물체 기억 쪽이 밀리면 장면 줄에서 오래된 장면부터 버린다(그래프 블록은 버리지 않음). NPU 자리를 기다리던 분할 장면은 새 장면이 대신한다.

## 개발 환경

- 저장소 경로는 공백·한글 없이(`C:\ondevice`). DEEPX 도구가 이런 경로에서 깨진다.
- 빌드 기능: PC 기본(CPU, Rust 실행기), 보드 `--no-default-features --features dxrt`(DXRT 만).
- 평가 표: `target/release/bench [--quick]` — TUM 책상·사무실을 정해진 조건으로 돌려 위치 오차·실패·속도·물체 수를 한 표로.
- 다른 카메라 RGB-D 를 TUM 형식으로: `rgbd2tum <원본> <출력(이름에 freiburg3)> fx fy cx cy <깊이 1 m 값>` — TUM fr3 보정값 640×480 으로 다시 그려 RTAB-Map `rtabmap-rgbd_dataset`·`ondevice --slam "--tum …"` · `ondevice --tum` 이 같이 읽음. 다른 SLAM 위치로 돌리기: `ondevice --tum <폴더> --gt <위치 파일>`, 정렬 후 위치 오차: `ate <추정> <정답>`(기억 폴더에 `poses_est.txt`·`poses_map.txt` 를 남김).
