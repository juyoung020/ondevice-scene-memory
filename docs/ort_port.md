# ort → Rust 이식 기록

## SigLIP2 글 인코더 (viewer/sgview/src/textnet.rs)

- sgview 에서 ort 제거, 기능 이름 `search`. 가중치 재배치, F16C/FCVTL, AVX-512/AVX2/NEON FMA 커널, qkv 합침, exp/GELU 다항 근사.
- 대조(데스크톱 WSL, 1,352 문장, ort 출력 기준): 최소 코사인 0.9999983, 최대 |오차| 4.95e-3.
- 검색 순위(문장끼리 최근접): 번호 기준 1위 일치 97.9 %, 상위 10 겹침 99.7 %. 어긋난 28 개는 전부 목록에 같은 문장이 두 번 든 경우(예: 'bed' 두 번)라 ort 쪽 점수 차가 정확히 0 인 동점 — 글자 기준 1위는 1,352 개 모두 일치(어긋남 0). 근사 탓이 아니므로 exp/GELU 다항 근사(상대 오차 ~1e-7)는 그대로 둔다. 점수 최대 |차| 1.96e-4.
- GELU 를 fc1 행렬곱 끝(열 묶음이 캐시에 있을 때)에 바로 적용 — 따로 돌던 전체 패스(문장당 8–10 ms) 제거, 결과 비트 같음.
- 속도(문장당 중앙값, 40 문장, 부하 평균 12–14): 4 스레드 Rust 34.9 ms / ort 41.2 ms, 8 스레드 Rust 42.7–45.5 ms / ort 47.2–49.6 ms. 16 스레드는 다른 작업과 겹쳐 둘 다 느림(Rust 90.6 / ort 68.2) — 데스크톱은 8 스레드 이하 권장. 보드 확인 필요.

## ONNX 실행기 (common/src/nn)

ort 대신 .onnx 를 Rust 로 직접 돌린다. 쓰는 곳: MegaLoc · XFeat(`slam/src/nnrun.rs`), SigLIP2 그림 인코더(`pipeline/src/embed.rs`), ObjectSAM(`pipeline/src/seg.rs`). 저장소에서 ort · ndarray 의존과 `directml` 기능, `common::ort` 를 뺐다.

- 읽기: protobuf 를 직접(그래프 · 초기값 · Constant · 속성). 불러올 때 상수 접기(입력이 모두 상수인 노드), 묶기 — Conv + Relu/SiLU, MatMul + 편향, LayerNorm(ReduceMean … Div [· γ · β]) 한 노드, 행렬곱 · 합성곱 뒤 원소별 노드 줄(상수 스칼라만 받는 것: GELU tanh · 잘린 GELU 등)을 출력 쓰기 때 한 번에.
- 행렬곱(`gemm.rs`, MatMul · Gemm): A 는 MR 줄 묶음, B 는 32 열 판, k 는 256 씩(판 조각이 L1 에 머묾). AVX-512(MR 12) · AVX2 · NEON 커널. 상수 무게는 불러올 때 판으로, 상수 아닌 B 는 판마다 펴서(Gather).
- 합성곱(`nchwc.rs`): 모델 전체를 NCHWc 배치로 유지 — 채널을 B 개(AVX-512 16, NEON · 그 밖 8)씩 묶어 [N][C/B][H][W][B], 한 화소의 B 채널이 연속. 커널은 MLAS ConvNchwcFloatKernel 방식: 입력 값 하나를 퍼뜨려 출력 묶음 fb 개 × 화소 px 개 누적에 FMA(AVX-512 4 × 6 · 3 × 8 · 2 × 8 · 1 × 16, NEON 2 × 6 · 1 × 12). 곱셈-덧셈 차례는 입력 묶음 → (ky, kx) → 묶음 안 채널, 합은 0 에서 시작, 끝에 편향 · 활성(Relu · SiLU 는 커널 끝에서 레지스터로, 그 밖 원소별 줄은 타일 버퍼에서). 무게는 처음 쓸 때 [출력 묶음 무리][C/bi][kh][kw][bi][fb][B] 로(입력 묶음 크기 bi 별로 한 번).
  - 첫 층 · 채널 4 이하 텐서는 NCHW 를 그대로 읽음(묶음 크기 1). 채널이 B 배수가 아닌 텐서(XFeat 24 · 65 · 8)는 남는 칸을 덧대고, 마지막 입력 묶음은 실제 채널 수(4 · 8 로 올림)까지만 곱함. 출력 채널 B/4 이하(XFeat 1 · 4, ObjectSAM 머리 4 · 1)는 NCHW 로 바로(채널마다 화소를 모아 이어 씀) — 덧댄 칸이 대부분인 큰 평면을 쓰고 읽는 흐름을 없앰.
  - 가장자리(덧댐에 걸리는 화소)는 화소 하나씩 탭 범위를 줄여서, 가운데는 큰 타일. 일 = (출력 줄 묶음, 출력 묶음 무리 범위).
  - 1×1 · 보폭 1 은 평면을 한 줄로 펴 240 화소 조각마다, 입력 채널 128 개씩 나눠(그 무게 ≤ 32 KB 가 L1 에) 조각 합을 일꾼 버퍼에 이어 더함, 입력은 두 타일 앞 미리 읽기.
  - ConvTranspose(보폭 = 크기)는 입력 화소마다 1×1 합성곱으로 kh · kw · Co 값(가상 출력 묶음 = 탭 · 묶음)을 내어 출력 자리(화소 간격 kw · B)에 바로.
  - 채널별(depthwise)은 묶음 평면에서 화소마다 B 칸을 탭 차례로 곱해 더함(가운데 화소는 범위 계산 없이).
  - Concat → Conv, Split → Conv 묶기(`fuse_cat`): 조각들이 모두 NCHWc 이고 채널 경계가 B 배수면 묶음 평면 주소를 그대로 읽음(아니면 NCHW 채널 평면).
- NCHWc 를 그대로 읽는 노드: Conv · ConvTranspose · 원소별(같은 모양 둘 또는 값 하나) · Relu 등 한 입력 · Concat · Split(채널 축, 경계 B 배수) · Resize · MaxPool · AveragePool. 그 밖(ObjectSAM 머리 Reshape · Transpose · MatMul · Softmax · TopK 등)과 모델 출력 앞에서만 NCHW 로 바꿈(`nchwc::accepts`).
- 넓은 벡터 기능: 묶음 16 인 채널별 · 풀링 줄은 AVX-512 기능을 켠 함수로 따로 컴파일(클로저 안에서 부르면 기능 없는 판으로 남을 수 있음). 커널 하나하나도 따로 둔 함수(큰 분기 함수에 모두 펼치면 누적이 레지스터에 머물지 못하는 판이 생겼다).
- 일꾼(`pool.rs`): 전용 스레드 묶음이 일을 나눠 갖고, 끝나면 2 ms 돌며 다음 일을 기다린 뒤 잠든다. 이 PC WSL 에서 rayon 은 부를 때마다 잠든 스레드를 깨우느라 호출당 0.1–0.8 ms 가 들어 8 스레드가 1 스레드보다 느렸다(MegaLoc 404 ms ↔ 384 ms). 모델마다 일꾼 상한(`set_threads`: 분할 ≤ 8, 사진 벡터 2, nnrun 은 넘겨받은 수).
- 버퍼(`buf.rs`): 다 쓴 f32 버퍼를 되받아 다음 노드 출력에 씀(XFeat 한 번의 페이지 부재 약 3,600 → 거의 0). 첫 입력을 마지막으로 쓰는 모양 바꾸기 · 원소별 노드는 버퍼째 넘겨 받아 제자리 계산.

### 속도 (데스크톱 WSL, Ryzen 9 9950X, 다른 세션 부하 평균 9–14)

ort 1.31 · 앞 판(7c39240, NCHW 합성곱) · 지금을 같은 코어에 고정해 번갈아 각 판 20–40 번 돌린 최솟값(앞 몇 번은 무게 펴기 · 버퍼 되쓰기가 자리 잡느라 느림). 1 · 4 스레드 `~/nnref/tools/ab1.sh`(4 스레드는 서로 다른 물리 코어 8,10,12,14), 8 스레드 `ab.sh`. ms.

| 모델 | 1 스레드 ort / 앞 판 / 지금 | 4 스레드 ort / 앞 판 / 지금 | 8 스레드 ort / 앞 판 / 지금 |
|---|---|---|---|
| ObjectSAM | 40.1 / 53.3 / **42.0** | 13.8 / 16.9 / **13.8** | 11.6 / 12.7 / **11.1** |
| XFeat | 12.9 / 13.4 / **13.1** | 4.31 / 3.97 / **4.11** | 3.32 / 3.30 / **3.05** |

- MegaLoc · SigLIP2 그림은 합성곱이 없거나(MegaLoc) 첫 층 하나뿐이라 앞 판과 같음(8 스레드 MegaLoc ort 49.1 / 앞 판 45.0 / 지금 47.7, SigLIP2 앞 판 18.0 / 지금 17.8 — 부하 흔들림 안).
- 1 스레드는 ObjectSAM 이 ort 보다 약 5 %, XFeat 약 2 % 느림. 노드별 최솟값 합은 ObjectSAM 40.5 대 ort 41.1(ort 프로파일, QuickGelu · Reorder 포함)로 같음 — 3×3 합성곱은 두 쪽 모두 FMA 한계(약 300 GFLOPS)이고, 남는 차이는 모델 출력 NCHW 바꾸기 · 작은 노드(Transpose 0.37 대 0.05, Softmax 0.38 대 0.12, MatMul 0.67 대 0.51 ms)와 XFeat 앞단 큰 평면 작은 채널 층(1→4 · 4→8 · 8→8, 메모리 흐름).
- ort 노드별 프로파일: `~/nnref/tools/ortprof.py`(저장소 밖, T=스레드), 우리 쪽 `~/nnref/tools/prof.py`(NN_PROF=2 여러 번의 노드별 최솟값 · GFLOPS).

### 일꾼 깨우기

잠든 일꾼이 없으면 깨우기 시스템 호출 · 잠금을 건너뜀. 행렬곱 · 합성곱은 일 크기에 맞춰 일꾼 수를 줄임(곱셈-덧셈 2 M 개당 하나).
