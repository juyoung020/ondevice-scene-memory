# 평가 계획 (향후 과제)

지금(2026-11-04)은 같은 장면을 PC 와 Pi5 에서 돌려 화면·물체 수·처리 속도만 비교했다. 아래는 최종 발표 전까지 갖출 정량 평가다.

## 1. 속도 (FPS)
- 단계별 시간(ms/키프레임): 영상 읽기 · 분할(NPU 실행 / 전후처리 나눠서) · 깊이 · 지도 · 물체 · 기록 — `ondevice` 가 25 키프레임마다 찍는 값을 표로.
- 끝에서 끝까지 처리량(키프레임/초)과 카메라 프레임 기준 실시간 여부(30 fps 입력에서 키프레임 몇 Hz 를 유지하나).
- Pi5 쪽: NPU 비동기 실행(`dxrt_engine_run_async`)으로 분할과 지도를 겹쳤을 때, 전력·온도(`dxrt-cli`)와 함께.
- 목표: 키프레임 ≥ 10 Hz(현재 Pi 8.8).

## 2. 분할 정확도 (프레임 단위)
정답: TUM·ScanNet++ 등 사람 라벨(또는 수동 라벨 소량).
- 마스크 **IoU**, 물체 단위 **Precision · Recall · F1**(IoU ≥ 0.5 매칭), **mAP@0.5 · mAP@0.5:0.95**(COCO 방식).
- COCO YOLO26s-seg vs ObjectSAM(v21L, 재학습 후) vs NPU 양자화판(.dxnn) — 양자화로 잃는 mAP.

## 3. 물체 기억 정확도 (3D, 시퀀스 단위)
정답: 장면의 실제 물체 목록 + 3D 위치(수동 또는 ScanNet++ 메쉬 라벨).
- 물체 단위 **Precision**(기억한 물체 중 진짜) · **Recall**(진짜 물체 중 기억한 것) · **F1**.
- 같은 물체 중복률(한 물체가 여러 개로 기억된 비율), 3D 위치 오차(m), 3D 상자 **IoU**.
- 이름 **정확도**(accuracy, 매칭된 물체 중 이름이 맞는 비율).
- 사라짐 판정: 옮긴 물체를 'moved/gone' 으로 바르게 바꾼 비율.

## 4. 지도·위치
- 위치: ATE RMSE(m)·경로 길이 대비 %(지금 ADVIO VIO 0.64 m).
- 3D 점 지도: 정답 깊이(Kinect)로 만든 지도와의 점-점 거리(Chamfer).
- 방: 방 개수·이름 정확도(사람이 정한 방 구분과 비교).
